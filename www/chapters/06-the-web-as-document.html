Part II: The Web

Chapter 06

#The Web: the shape of words

A URL can point to a document, but once the browser gets there, how does it know what to show you? This is where the Web reveals another invention made mostly from stolen goods: HTML, or HyperText Markup Language.

We've met hypertext and language already, but what is markup doing here? It's older than you might think. Certainly older than computers.

https://chnm.gmu.edu/digitalhistory/links/pdf/chapter3/3.19a.pdf https://en.wikipedia.org/wiki/Letterpress_printing https://en.wikipedia.org/wiki/Offset_printing Markup is simply extra marking on a document that tells someone what to do with it. Before computers, it belonged to the print trade (here is a brief history of document markup). In letterpress and later offset printing, an editor marked up a manuscript with a pencil before sending it to the typesetter: a person who built each page out of movable type, small metal blocks each carrying a single letter or glyph. https://chnm.gmu.edu/digitalhistory/links/pdf/chapter3/3.19a.pdf https://en.wikipedia.org/wiki/Letterpress_printing https://en.wikipedia.org/wiki/Offset_printing

The markup told the typesetter which font and size to use, and made the other layout decisions.

Early computers printed like typewriters. If you wanted decent printed output, you attached a phototypesetter: a complex machine of its own that could be told which fonts and sizes to use. Each one had its own vendor-specific commands and software.

https://en.wikipedia.org/wiki/Troff The wizards at Bell Labs, who were busy inventing Unix, were not impressed. They wanted their Unix and C manuals nicely typeset without fiddling with the machine. So they wrote troff, one of the earliest markup languages for computers. It is still with us: every Unix system has a manual command, man, and its pages are marked up in a troff descendant. https://en.wikipedia.org/wiki/Troff

https://en.wikipedia.org/wiki/Donald_Knuth https://en.wikipedia.org/wiki/The_Art_of_Computer_Programming Another wizard, Donald Knuth, wanted to write a book about programming. Well, actually, he wanted to write the book on programming. In 1962 Addison-Wesley asked him for a book on compilers, and he enlarged the scope a bit: a planned seven volumes, the first three published by 1973. Then the publisher switched from hot-metal type to phototypesetting, and the proofs of a new edition came back looking terrible. Clearly that was unacceptable to a proper wizard. https://en.wikipedia.org/wiki/Donald_Knuth https://en.wikipedia.org/wiki/The_Art_of_Computer_Programming

https://tug.org/whatis.html https://www.latex-project.org/ So in 1977 he set the books aside to write his own typesetting system. He expected it to take a few months. It took the better part of a decade, and produced TeX. Built on top of it, LaTeX is still how many mathematicians, physicists and computer scientists write their papers. TeX itself is famously close to bug-free, partly because Knuth froze it. Its version number no longer grows; it just adds another digit of π. https://tug.org/whatis.html https://www.latex-project.org/

Both troff and TeX exist to put documents on paper. Their markup says how the text should look, not what it is.

https://en.wikipedia.org/wiki/IBM_Generalized_Markup_Language This is where things get interesting. In 1969, three IBM wizards, Goldfarb, Mosher and Lorie, created GML. Officially it stands for Generalized Markup Language. It also happens to spell their initials. GML described what each part of a text was: a heading, a paragraph, a list item. How it should look was left to someone else. Here is an example: https://en.wikipedia.org/wiki/IBM_Generalized_Markup_Language

https://en.wikipedia.org/wiki/Standard_Generalized_Markup_Language https://html.spec.whatwg.org/ GML grew into SGML—the Standard Generalized Markup Language, which became an international standard in 1986. SGML itself has no tags. It is a language for defining document formats, each described by a DTD—a Document Type Definition. Powerful, and far too heavy for what Sir Tim needed. But CERN already had a simple SGML format of its own, with short tags inherited from GML: h1, p, ol, li. HTML borrowed them. Stolen goods, once again. https://en.wikipedia.org/wiki/Standard_Generalized_Markup_Language https://html.spec.whatwg.org/

Here is the page from the previous chapter again:

https://html.spec.whatwg.org/multipage/introduction.html#history-2 It is not an SGML document: it has no DTD. HTML 2.0 was later formally defined in SGML, until HTML5 dropped it again. https://html.spec.whatwg.org/multipage/introduction.html#history-2

It does use the SGML way of separating markup from content: every tag sits between < and >.

Why this format? One goal of the Web was that anyone could write HTML in an ordinary text editor. So the source had to stay readable. Named closing tags make it clear which element is ending.

Another consequence of the format is that some characters can no longer be used freely in the content. < now has a special meaning, and so do > and ". HTML solves this with character references, another escape:

  • < as &lt;
  • > as &gt;
  • " as &quot;

But now & has become special as well. Easily solved:

  • & as &amp;

And these are the basics of HTML.

https://en.wikipedia.org/wiki/WYSIWYG https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/contenteditable If you really want to open a can of worms, try writing a rich text editor in HTML, fully WYSIWYG (What-You-See-Is-What-You-Get). Browsers even include one. The contenteditable attribute turns it on: https://en.wikipedia.org/wiki/WYSIWYG https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/contenteditable

What you get is an editor Microsoft designed for Internet Explorer 5.5, which other browsers then copied, quirks and all. Its capabilities are dreadfully limited, and the HTML it produces differs from browser to browser. Standards groups have spent years trying to specify something better. Those efforts stalled.

The in-browser editors that do work well, and produce clean HTML, mostly avoid editing HTML directly. They convert the document to a different model of their own, let you edit that, and convert it back to HTML when you save.

The lesson: just because something looks simple doesn't mean it is. All choices have consequences. If you're careful, you can decide which ones you want to live with.
